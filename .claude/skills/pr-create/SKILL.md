# PR Create Skill

Create a well-structured GitHub Pull Request from the current branch into `main`.

## Step 1: Validate Branch State

```powershell
git status
git branch --show-current
git log main..HEAD --oneline
git diff main...HEAD --stat
```

- If the current branch IS `main`, stop and ask the user which feature branch to use.
- If there are unstaged changes, recommend running the `git-commit` skill first.
- Count commits in the branch — this drives the PR description body.

## Step 1a: SharedVSCode TemplateRef Validation

If the PR targets `main`, check that all `.code-workspace` files have their
`atap.sharedVSCode.templateRef` set to `"main"`:

```powershell
Import-Module ATAP.Utilities.BuildTooling.PowerShell -Force

$workspaceFiles = @(Get-ChildItem -Path (git rev-parse --show-toplevel) -Filter '*.code-workspace' |
    Select-Object -ExpandProperty FullName)

if ($workspaceFiles.Count -gt 0) {
  try {
    Assert-MainBranchTemplateRef -WorkspaceFiles $workspaceFiles
    Write-Host 'SharedVSCode templateRef check passed.'
  }
  catch {
    Write-Warning $_
  }
}
```

Use the installed Production module on this validation path; do not fall back
to the historical SharedVSCode source-tree loader.

If the assertion fails, **warn the user** that workspace files still reference a sprint
worktree. Ask whether to:

1. Run `Reset-DownstreamToSharedVSCodeMain -WorkspaceFiles $workspaceFiles`, commit the
   change, then continue creating the PR.
2. Continue anyway (the PR reviewer / merge gate will catch it).
3. Abort PR creation.

This is a **warning, not a hard block** — the user may intentionally create a PR with a
sprint `templateRef` for review purposes.

## Step 1b: Large-PR Risk Assessment (SC-0117D)

Count the files changed in this branch relative to `main`. If the count meets or
exceeds the threshold (100 files), a `## Risk Note` section **must** be injected
into the PR body in Step 3.

```powershell
$changedFiles  = (git diff --name-only main...HEAD | Measure-Object).Count
$commitCount   = (git log main..HEAD --oneline | Measure-Object).Count
$largePrThreshold = 100

if ($changedFiles -ge $largePrThreshold) {
    Write-Warning (
        "Large PR detected: $changedFiles files changed across $commitCount commit(s). " +
        "A Risk Note section will be injected into the PR description (SC-0117D)."
    )
    # Identify the highest-churn directories to surface as high-risk areas
    $topDirs = git diff --name-only main...HEAD |
        ForEach-Object { ($_ -split '/')[0] } |
        Group-Object | Sort-Object Count -Descending |
        Select-Object -First 5 |
        ForEach-Object { "$($_.Name) ($($_.Count) files)" }
    $topDirsText = $topDirs -join ', '
    $script:largePrRiskNote = @"

## Risk Note ⚠️ (Large PR — $changedFiles files, $commitCount commits)
This PR touches a large number of files. High-risk areas to review carefully:
- $topDirsText

Deferred validation items (verify after merge):
- Integration tests across all affected areas
- NuGet package version consistency if `.csproj` files are included
- Database migration ordering if migration files are included
"@
} else {
    $script:largePrRiskNote = $null
}
```

Carry `$script:largePrRiskNote` forward to Step 3 — append it after the `## Notes`
section when non-null.

## Step 2: Push Branch to Remote

Push the branch if it hasn't been pushed yet, or if it's ahead of origin:

```powershell
git push --set-upstream origin (git branch --show-current)
```

## Step 3: Compose the PR

### Title

Follow Conventional Commits style (same as commit messages):

```text
<type>(<scope>): <concise summary of the entire branch's purpose>
```

- Derive from the branch name and commit log — don't just copy the last commit
- Max 72 characters, imperative mood, lowercase after colon

### Body Template

```text
## Summary
<2-3 sentence description of what this PR accomplishes and why>

## Changes
- <key change 1>
- <key change 2>
- <key change 3>

## Testing
- <how was this tested or validated>

## Notes
<breaking changes, follow-up work, migration steps, or "None">

Closes #<issue number if applicable>
```

Populate each section from the commit log and diff stat. Be specific — avoid
generic filler like "various improvements". If no issue number exists, omit
the `Closes` line.

If `$script:largePrRiskNote` is non-null (set in Step 1b), append it after
`## Notes` so reviewers see the risk summary before approving.

## Step 4: Create the PR

```powershell
gh pr create `
  --base main `
  --title "<title>" `
  --body "<body>" `
  --draft
```

Default to `--draft` unless the user explicitly says the branch is ready for review.
Remove `--draft` and add reviewers only when the user confirms it's review-ready.

## Step 5: Confirm

Run `gh pr view` and report back the PR number, URL, title, and status.
