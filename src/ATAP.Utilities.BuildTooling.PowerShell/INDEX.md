# ATAP.Utilities.BuildTooling.PowerShell - Project File Index

This index lists every file currently in the BuildTooling PowerShell project and gives a high-level purpose for each one. Regenerate it whenever files are added, removed, or moved.

## Project Shape

- `public/` contains exported cmdlets and developer-facing workflows.
- `private/` contains internal helpers dot-sourced by the module.
- `tools/` contains loose workstation or development setup scripts that are not exported cmdlets.
- `tests/` contains Pester coverage and fixtures.

The ten Pester configuration and test-template commands are now owned by
`ATAP.Utilities.BuildTooling.PesterScaffolding.PowerShell`. The parent imports that
child and retains parameter-preserving compatibility exports during the migration.
The Git/worktree commands are owned by
`ATAP.Utilities.BuildTooling.GitWorktree.PowerShell` 0.1.2 or later and are likewise
re-exported through parameter-preserving parent compatibility proxies.
Database package evidence, compatibility, feed, and SQL-instance commands are owned
by `ATAP.Utilities.BuildTooling.DatabasePackaging.PowerShell`; the parent retains
the frozen legacy command names through compatibility proxies.
Three non-exported parent dispatch shims temporarily preserve private helper calls
from remaining Sprint and scope-creep commands until those consumers move.
The accepted compatibility deployment is parent 0.1.52 with GitWorktree 0.1.2;
parent 0.1.49 is the rollback and parent 0.1.50/0.1.51 are burned.
- `Resources/`, `Documentation/`, and `Obsolete/` hold support files, docs, and retained historical scripts.
- `Obsolete/private/` retains retired internal helpers (e.g. the per-sprint ProGet feed and per-sprint database/BuildMaster scaffolding) for provenance only; no current cmdlet dot-sources them.
- Sprint planning boards now flow from authoritative `TASKS.md` to generated `TASKS.html` via `Convert-TasksMdToSprintBoard`.
- `Save-SprintWorkSession` now appends a lightweight `SprintWorkSessionRoster/SprintWorkSessionRoster-<NNNN>.jsonl` file in the sprint `_Planning` worktree so SprintEnd can verify archive coverage by worktree name. ClaudeCode project folders are resolved case-insensitively from `~\.claude\projects` before copying memory files.

## Sprint Lifecycle Flow

The public sprint helpers are driven by two runbooks in the SharedVSCode `.claude/agents/` folder. Use this section as the index back into the per-cmdlet entries below.

**Runbooks:**

- [SprintStartAgent](../../../../SharedVSCode/.claude/agents/SprintStartAgent.md) — opens a new sprint: SharedVSCode + downstream worktrees, junctions, sprint secrets, sprint SQL instances, BuildMaster sprint variables, sprint overview workspace.
- [SprintEndAgent](../../../../SharedVSCode/.claude/agents/SprintEndAgent.md) — closes a sprint: retrospective snapshot, downstream reset to main, sprint secret/instance/variable cleanup, sprint workspace archival, generated-artifact purge.

**Canonical sprint-boundary retargeting (V4-H03):**

- [Set-SprintBoundaryContext.ps1](public/Set-SprintBoundaryContext.ps1) — single orchestrator that retargets machine links (junctions), SharedVSCode settings symlinks, downstream workspace contexts, registry-backed AI adapters, and managed PowerShell profiles for one or more sprint worktrees. `-Boundary Start` points everything at the SharedVSCode sprint worktree; `-Boundary End` audits adapter drift before pointing it back to stable and recreates only the supported stable `.vscode` junction by default, rather than obsolete `.claude` / `.github` links. The shared settings render is refreshed at both boundaries so trusted directories and hook command paths follow the active target. The cmdlet copies the selected ATAP.IAC payload into the machine, developer, and service-account profile paths and retargets the separate HostSettings link. See [Sprint-Boundary-Retargeting.md](../../../SolutionDocumentation/Sprint-Boundary-Retargeting.md). Task 12.2.b: this cmdlet is now the SINGLE Start entry point for per-worktree provisioning (junctions -> downstream context -> full adapter materialization, structurally ordered); `New-SprintStage1`/`New-SprintStage2` delegate here (with `-SkipSharedVSCodeSettings`/`-SkipProfileSymlinks`, retained compatibility parameter name) instead of orchestrating junctions and renders themselves, and SprintEndAgent calls this cmdlet directly for the End boundary.

- [Sync-SprintBoundaryPrimaryRoleMarker.ps1](public/Sync-SprintBoundaryPrimaryRoleMarker.ps1) — validates the stable Dropbox-synchronized Task 12.59 role marker at both sprint boundaries, atomically migrates a lone legacy ProgramData marker, and refuses conflicting copies without changing the authorized role.

- [Invoke-SprintAIAdapterLifecycle.ps1](public/Invoke-SprintAIAdapterLifecycle.ps1) — loads the canonical SharedVSCode registry-backed lifecycle. Start renders the canonical adapter domains and End audits those same domains for drift before teardown. `Set-SprintBoundaryContext` also reuses the Start render against the selected SharedVSCode target at both boundaries so `settings.overlay.json` output stays synchronized before relinking user settings. Caller order is Antigravity → Codex → Claude Code → Copilot; production defaults are project-only, and live user/global replacement requires explicit approval plus checkpoint confirmation.

- [Convert-StableWorktreeToConcreteAdapters.ps1](public/Convert-StableWorktreeToConcreteAdapters.ps1) — one-time stable-worktree repair helper for Task 12.1: removes legacy `.claude` / `.github` junctions with junction-safe `cmd /c rmdir`, refuses to proceed when staged changes exist under the target folder, then restores tracked concrete content from `HEAD`. `.vscode` is intentionally out of scope and remains a junction.

**Sprint start sequence (public cmdlets, in execution order):**

1. [Test-SprintPrerequisites.ps1](public/Test-SprintPrerequisites.ps1) — Step 0 preflight (ATAP configuration-global self-bootstrap for agent shells, pwsh, gh auth, Bitwarden, BuildTooling import, SQL instances, ProGet/BuildMaster reachability, and the Task 9.7 `-BuiltModule` promotion+deploy gate).
2. [Assert-BuildMasterReady.ps1](public/Assert-BuildMasterReady.ps1) — Step 0 preflight (BuildMaster apps, pipelines, required application variables, API key); explicit and default secret names are profile-independent.
3. [New-SprintStage1.ps1](public/New-SprintStage1.ps1) — SharedVSCode + \_Planning sprint branches/worktrees, next-sprint detection via [Get-SprintHistoryReconstruction.ps1](public/Get-SprintHistoryReconstruction.ps1), prior-sprint structure-only task templating into the content-fresh `Tasks.Sprint<NNNN>.*` set, exact `.git` pointer ownership verification/repair, supported `.vscode` junction creation, AIAdapter materialization for generated agent surfaces, and permanent-feed NuGet.config (Task 10.11 / 11.19 / 13.5).
4. [New-SprintStage2.ps1](public/New-SprintStage2.ps1) — downstream sprint branches/worktrees, exact `.git` pointer ownership verification/repair, NTFS junctions, AI/settings links, compound `[RepoA + RepoB]` task-tag discovery, optional `-IncludeRepos`, and a durable `-SkipDatabaseReset` recovery path. After all sprint worktrees exist it generates and verifies `Overview.Sprint.NNNN.code-workspace`, preserving host-qualified multi-host developer assignments, then calls `Build-AIInstructionsPerRepository` once to distribute all four per-repository instruction surfaces (Task 10.34 / 13.63.a-b). The normal database path passes the new ATAP.Utilities worktree root and current provisioning-script folder with `-Confirm:$false`.
5. [Reset-SprintDatabases.ps1](public/Reset-SprintDatabases.ps1) — drop/recreate the single `ATAPUtilities` database inside the existing `Dev<user>`/`Exp<user>` instances (Flyway rebuild). An explicit `-ProvisioningScriptsPath` overrides stale host settings so the active worktree's `DropAndCreateDatabase.sql` is used; actual reset paths import `dbatools` before resolving `Build-DatabaseWithFlyway` to avoid `Microsoft.Data.SqlClient` load-order conflicts, connection-part resets default to integrated security when no secret or credential key is resolved, and missing `DatabasePath` values default to `C:\LocalDBs\<InstanceName>\<DatabaseName>`.
6. [New-SprintBitwardenSecrets.ps1](public/New-SprintBitwardenSecrets.ps1) — creates or verifies the per-sprint Dev/Exp connection-string secrets in Bitwarden Secrets Manager (Task 10.7 cleanup). Default path uses `bws` plus process `$env:BWS_ACCESS_TOKEN` override or `Get-BWSAccessToken -TokenPurpose ReadWrite` / `CommonCIForBitwardenReadWrite`; `BW_SESSION` is never involved. [Get-DbConnectionStringSecretDescriptor.ps1](public/Get-DbConnectionStringSecretDescriptor.ps1) owns the canonical name and provisioning value format.
7. [Set-BuildMasterSprintVariables.ps1](public/Set-BuildMasterSprintVariables.ps1) — sprint-scoped BuildMaster Application Variables.
8. [New-OverviewSprintWorkspace.ps1](public/New-OverviewSprintWorkspace.ps1) — `Overview.Sprint.NNNN.code-workspace` for the active sprint; developer identity is `(username, host)`, multi-host assignments are deterministic, and existing configured assignments survive regeneration.
9. [Remove-OverviewSprintWorkspace.ps1](public/Remove-OverviewSprintWorkspace.ps1) — archive the exact closing-sprint Overview workspace into `_Planning/SprintRetrospective/WorkspaceArchive/`, preferring `Overview.Sprint.NNNN.code-workspace` when present and falling back to explicitly supported legacy names.
10. [Build-CLAUDEPerRepository.ps1](../ATAP.Utilities.BuildTooling.AiRendering.PowerShell/public/Build-CLAUDEPerRepository.ps1) — combined `CLAUDE.md` per repo worktree.
11. [Build-AGENTSPerRepository.ps1](../ATAP.Utilities.BuildTooling.AiRendering.PowerShell/public/Build-AGENTSPerRepository.ps1) — combined `AGENTS.md` per repo worktree: `ai-local.md` (AI-LOCAL) + rendered `AGENTS-base.md` core (AI-CORE), deterministic sentinels, idempotent (Task 10.23). Sibling of `Build-CLAUDEPerRepository`.
12. [Build-AgentSpecificPerRepository.ps1](../ATAP.Utilities.BuildTooling.AiRendering.PowerShell/public/Build-AgentSpecificPerRepository.ps1) — distributes the rendered agent-specific surfaces `GEMINI.md` and `.github/copilot-instructions.md` into each sprint repo (pure idempotent copy, stable-skip guard, and no-double-core validation).
13. [Build-AIInstructionsPerRepository.ps1](../ATAP.Utilities.BuildTooling.AiRendering.PowerShell/public/Build-AIInstructionsPerRepository.ps1) — single SprintStart orchestration entry point; parses the Overview workspace once, computes stable-worktree skips once, runs the three existing lane builders in canonical order, and returns per-lane plus per-repository aggregate results (Task 10.34). Called by `New-SprintStage2`.

**Sprint end sequence (public cmdlets, in execution order):**

1. [Invoke-SprintEndLifecycle.ps1](public/Invoke-SprintEndLifecycle.ps1) — typed orchestrator; always run the selected close with `-WhatIf` first. The close plan always includes the active `_Planning` worktree and reports PR, merge, branch-delete, and worktree-removal intent for each target.
2. [Test-SprintEndCommandSurface.ps1](public/Test-SprintEndCommandSurface.ps1) and [Test-SprintPrerequisites.ps1](public/Test-SprintPrerequisites.ps1) — validate real parameter contracts and require every changed module version in ProGet stable plus an AllUsers installation.
3. [Test-SprintEndWorktreeState.ps1](public/Test-SprintEndWorktreeState.ps1) — one structured multi-worktree clean-state gate.
4. [Test-SprintCheckpointCoverage.ps1](public/Test-SprintCheckpointCoverage.ps1) — require a reachable agent-neutral checkpoint for every selected worktree using only canonical Planning roots.
5. [Set-SprintBoundaryContext.ps1](public/Set-SprintBoundaryContext.ps1), [Reset-DownstreamToSharedVSCodeMain.ps1](../ATAP.Utilities.BuildTooling.AiRendering.PowerShell/public/Reset-DownstreamToSharedVSCodeMain.ps1), and [Assert-MainBranchTemplateRef.ps1](public/Assert-MainBranchTemplateRef.ps1) — audit AIAdapter drift and commit stable-target references on sprint branches before merge.
6. [Invoke-SprintEndGitHubClose.ps1](public/Invoke-SprintEndGitHubClose.ps1) — add `Closes #N`, run the SprintEnd GitHub token-scope preflight (`read:org` or `read:discussion`) ahead of GraphQL-backed PR calls, classify required/informational/CodeSee checks, merge non-interactively, and verify the sprint issue closed.
7. [Save-SprintHistoryArtifacts.ps1](public/Save-SprintHistoryArtifacts.ps1), [Restore-SprintHistoryArtifacts.ps1](public/Restore-SprintHistoryArtifacts.ps1), and [Invoke-SprintEndOverviewClose.ps1](public/Invoke-SprintEndOverviewClose.ps1) — archive current dotted history, explicitly reconstruct reviewed older history with exact Git blob bytes and source-relative paths without overwriting different content, and archive the parent-root sprint Overview workspace using the exact closing sprint number.
8. [New-SprintEndHandoff.ps1](public/New-SprintEndHandoff.ps1) — atomic, self-removing `HANDOFF.SprintNNNN.md` worktree cleanup handoff. Stable pulls call [Test-SprintEndPullOverlap.ps1](public/Test-SprintEndPullOverlap.ps1) before `pull --ff-only`, and generated command blocks are parser-safe.
9. [Save-SprintEndSessionTail.ps1](public/Save-SprintEndSessionTail.ps1) — checkpoint and commit only the canonical final conversation/memory/roster tail after the Planning PR merges; never pushes automatically.
10. [Invoke-SprintEndInfrastructureCleanup.ps1](public/Invoke-SprintEndInfrastructureCleanup.ps1) — drop sprint databases, retain permanent SQL Server instances, clear BuildMaster sprint variables, and reassert the stable boundary.
11. [Test-SprintEndBoundaryState.ps1](public/Test-SprintEndBoundaryState.ps1) — final stale-reference, developer/service profile, fresh-shell, and prohibited-secret-environment audit.

SprintEnd never calls `Remove-SprintBitwardenSecrets`; it removes sprint
databases while retaining permanent SQL Server instances, and never completes a
synthetic "close sprint" task.

**Permanent (ecosystem-wide) sprint infrastructure, not per-sprint:**

- ProGet feeds are permanent: `nuget-experimental`, `nuget-development`, `nuget-integration`, `nuget-qa`, `nuget-stable`, plus the parallel `powershellget-*` and `universal-*` feed families. See [Set-BuildMasterStableVariables.ps1](public/Set-BuildMasterStableVariables.ps1) for permanent provisioning. The old per-sprint ProGet feed helpers were retired in Sprint 0007 (task B08) and live under `Obsolete/private/`.
- **Secrets policy (Task 9.21 / Task 10.7):** CI/infrastructure secrets (connection strings, ProGet/BuildMaster API keys, service-account creds) live ONLY in Bitwarden Secrets Manager (bws + DPAPI machine/user access token via [Get-SecretATAPBitwardenSecretsManager.ps1](public/Get-SecretATAPBitwardenSecretsManager.ps1)). They must never live in a developer's personal Bitwarden Password Manager vault. [Get-SecretATAP.ps1](public/Get-SecretATAP.ps1) defaults to Secrets Manager for all accounts (SC-0175); the personal-vault provider [Get-SecretATAPBitwarden.ps1](public/Get-SecretATAPBitwarden.ps1) is opt-in only and now **refuses CI/infra secret names**. The personal-vault `bw`/BW_SESSION writer + service-account session machinery (`New-PermanentBitwardenSecrets`, `Initialize-ServiceAccountBitwardenSession`, `Refresh-BWSession`, `Update-ServiceAccountBWCredentialFile`) was retired to `Obsolete/public/`.
- **ProGet administration boundary (Task 13.62):** callers pass only `ProGet.Admin.API.Key` as `-ProGetApiKeySecretName`; authenticated leaves resolve it and fail closed. See [ProGet administration SecretName boundary](Documentation/ProGetAdministrationSecretNameBoundary.md).
- **DB connection-string secrets (Task 10.7 cleanup):** Development and Experimental `dbConnectionString.*` values are BWS secrets. [New-SprintBitwardenSecrets.ps1](public/New-SprintBitwardenSecrets.ps1) creates/checks them in `CI-Shared`; [Get-DbConnectionStringSecretDescriptor.ps1](public/Get-DbConnectionStringSecretDescriptor.ps1) owns the canonical name and explicit provisioning value format; [Resolve-DatabaseSqlConnection](../ATAP.Utilities.DatabaseManagement.Powershell/public/Resolve-DatabaseSqlConnection.ps1) reads them through `Get-SecretATAP -SecretStoreType 'BitwardenSecretsManager'` and hard-fails if BWS cannot return the value.
