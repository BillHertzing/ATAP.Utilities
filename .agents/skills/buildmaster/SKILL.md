# AI instructions for BuildMaster integration

Rules for interacting with the organization's BuildMaster CI/CD server.
See `_Planning/Explainers/0004-BuildMaster-Setup.md` for full setup documentation.

---

## API Key Security

The API key is stored in the ATAP Secret Store (Bitwarden) and is exposed only as a
SecretName resolved through `Get-SecretATAP`. In agent shells, always read it that way.

The SecretName is **host-suffixed** as `<BaseName>.<placement-host>` (SC-0288),
because each BuildMaster instance has its own admin key. The suffix names the host
running the instance being authenticated against — not the host running the command —
so derive it from the service placement map rather than typing a host literal:

```powershell
$serviceHost = $global:Settings[$global:configRootKeys['ServicePlacementMapConfigRootKey']]['BuildMaster']
$apiKey = Get-SecretATAP -SecretName "BuildMaster.Admin.API.Key.$serviceHost"
```

BuildTooling cmdlets do this derivation themselves: leave
`-BuildMasterAdminApiKeySecretName` unbound and the cmdlet resolves the host-suffixed
name from the placement map, failing closed when placement is unknown. Bind the
parameter only to target a specific instance. See
`ATAP.Utilities/SolutionDocumentation/SecretName-HostSuffix-Convention.md`.

Not every credential is host-suffixed. A credential that authenticates the **caller**
rather than a placed service has the same value on every host and must be left alone —
in particular the Bitwarden Secrets Manager access token (`BWS_ACCESS_TOKEN`).

**Never hard-code or log the API key value.** In OtterScript plans, always use
`$Decrypt(...)` or a masked variable to prevent the key appearing in debug log output.

## Working Directory (Sprint Convention)

BuildMaster uses a `WorkingDirectory` Application Variable to know which sprint
worktree to build. At sprint start, update this variable to the current worktree path.
At sprint end (after merge to main), reset it to the permanent repo root.

Sprint boundary checklist:

- [ ] Sprint start: update `WorkingDirectory` in BuildMaster Application Variables
- [ ] Sprint end: reset `WorkingDirectory` to permanent repo path after merge

## Rotating the API Key

When rotating the BuildMaster API key (e.g., after a security incident):

1. Generate a new key in the BuildMaster admin UI (Admin → API Keys & Access Logs)
2. Disable or delete the old key
3. Update the ATAP secret-store item `ProGet.BuildMaster.API.Key.<service-host>` with
   the new value, where `<service-host>` is the placement host of the instance whose
   key you rotated
4. BuildMaster callers continue to pass that SecretName; the authenticated leaf
   resolves it with `Get-SecretATAP` immediately before use
5. Document the rotation in `_Planning/Explainers/0004-BuildMaster-Setup.md`

## OtterScript Authoring Gotchas (R-34)

Before authoring or modifying BuildMaster OtterScript, include concrete examples for the
syntax being changed and validate against a known-good plan. BuildMaster's DSL is close
enough to PowerShell to invite wrong assumptions, but its variable and masking syntax is
different.

Rules:

- Use `$EnvironmentVariable(NAME)` to read Windows environment variables. Do not use
  bare `$NAME` for machine environment variables; that reads a BuildMaster variable.
- Use `$Obscure(...)` or BuildMaster masked variables for secret values that may appear
  in logs.
- Prefer `InedoCore::Exec` for process execution. Do not assume shorthand `exec` is
  available or equivalent.
- Keep one minimal working OtterScript example near each new pattern added to the rules
  file or plan template.
- When an OtterScript change needs several retries, capture the final working syntax in
  this instruction file before moving on.

Example environment-variable usage (a non-secret variable — see the warning below):

```otter
set $BuildRoot = $EnvironmentVariable(ATAP_BUILD_ROOT);
Log-Information Building from: $BuildRoot;
```

> **Never read an API key from an environment variable.** `PROGET_ADMIN_API_KEY`,
> `PROGET_BUILDMASTER_API_KEY`, and `BUILDMASTER_ADMIN_API_KEY` were retired and
> deleted from every persistent scope; an OtterScript plan that reads one gets an
> empty value. Plans pass a **SecretName** as a non-secret variable, and the
> PowerShell leaf resolves it with `Get-SecretATAP` immediately before the
> authenticated call:
>
> ```otter
> InedoCore::Exec
> (
>     FileName: pwsh.exe,
>     Arguments: -NoLogo -NoProfile -File $ScriptPath -ProGetApiKeySecretName $ProGetApiKeySecretName
> );
> ```

Example process execution shape:

```otter
InedoCore::Exec
(
    FileName: powershell.exe,
    Arguments: -NoLogo -NoProfile -ExecutionPolicy Bypass -File C:\Path\To\Script.ps1
);
```
