# AceOutpost Metered Harness

Launch a Claude Code or Codex CLI child through the installed AceOutpost proxy without
putting proxy credentials or trust variables into the invoking agent, its shell, User
scope, or Machine scope.

## Use this skill when

- A task explicitly asks to run `claude -p`, `codex exec`, or a dispatched CLI agent
  through AceOutpost metering.
- An ATAP orchestration flow must start one non-interactive harness child and capture its
  stdout, stderr, and exit code.
- The user says “metered harness”, “through the AceOutpost proxy”, “proxied agent”, or
  asks for the Task 15.190 terminal-skill path.

Do not use this skill for the Codex app's native agent/subagent API. That path does not
spawn a caller-controlled CLI child and therefore cannot be wrapped by this process
adapter. Do not use it for an ordinary unmetered harness launch.

## Critical security boundary

1. Invoke `Invoke-AceOutpostMeteredPrompt` from installed
   `ATAP.Utilities.PowerShell` version 0.2.5 or later.
2. Never call `Set-AceOutpostProxyEnvironment` from this workflow.
3. Never assign `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`, `SSL_CERT_FILE`,
   `NODE_EXTRA_CA_CERTS`, or `NODE_TLS_REJECT_UNAUTHORIZED` in the invoking process.
4. Pass only a `CredentialSecretName`, never a credential value or credential-bearing
   proxy URL. Prefer the function's per-client default SecretName.
5. If the listener, interception root, module, or credential resolution fails, report
   “not metered; harness did not run.” Never fall back to an unproxied launch.
6. Keep prompts and extra CLI arguments as discrete array items. Never join or re-quote
   them into one command-line string.

## Workflow

1. Import the deployed module and require the terminal adapter:

   ```powershell
   Import-Module ATAP.Utilities.PowerShell -MinimumVersion 0.2.5 -ErrorAction Stop
   Get-Command Invoke-AceOutpostMeteredPrompt -ErrorAction Stop
   ```

2. Select the client and construct only the client-specific extra argument array:

   - `Codex`: use `Client = 'Codex'`. The adapter supplies `exec`, the end-of-options
     marker, and the prompt. Do not use `codex exec -p`; `-p` means profile in Codex.
   - `ClaudeCode`: use `Client = 'ClaudeCode'`. The adapter supplies `-p`, the
     invocation-scoped Node CA settings, the end-of-options marker, and the prompt. Do
     not pass `--settings`; the adapter reserves it for the required trust document and
     fails closed on a conflict.

3. Invoke the adapter with the prompt as one PowerShell value and each extra argument as
   a separate array item:

   ```powershell
   $invokeParameters = @{
     Client           = 'Codex'
     Prompt           = $promptText
     WorkingDirectory = $repositoryRoot
     ArgumentList     = @('--model', 'gpt-5.5')
     Confirm          = $false
   }
   $result = Invoke-AceOutpostMeteredPrompt @invokeParameters
   ```

   Omit `ArgumentList` when there are no extra client arguments. Do not pass an empty
   string in its place.

4. Treat the returned object as the process contract:

   - `Started = false`, a terminating exception, or a missing result means preflight
     refusal: report that the harness did not run.
   - `Started = true` with non-zero `ExitCode` means the metered harness ran and failed;
     report the exit code and sanitized stderr.
   - `Started = true` with `ExitCode = 0` means the metered harness completed; return its
     stdout and retain the invocation identifiers needed for listener-side correlation.

5. Never print the resolved environment block. Listener-side exchange evidence, the
   returned redacted metadata, and process ancestry are the supported acceptance signals.

## Nested dispatches

The adapter creates a new invocation identifier and passes an inherited identifier as
the parent identifier. The shared launch core overwrites both child markers so a nested
harness is not silently attributed to its grandparent. Do not replace, pre-populate, or
manually copy either `ACEOUTPOST_METERED_*` variable.

## Known coverage boundary

- Codex `shell_environment_policy.inherit = "core"` excludes proxy and CA variables.
  Therefore this workflow meters the `codex.exe` provider traffic, not the commands Codex
  starts as tools.
- Claude Code provider traffic uses the adapter-owned invocation-scoped CA settings.
  Claude tool shells inherit the harness block, so do not claim child-tool isolation;
  their traffic may also route through the listener.
- A source/test pass proves the adapter contract, not live provider metering. Live traffic
  remains a separately authorized acceptance gate.
