# Checkpoint Skill

Archive the current conversation and memory snapshot to the sprint `_Planning`
worktree so the session can be analyzed during the next pre-planning pass.

## 1. Identify the calling agent from system context

Determine your own calling-agent family from the system or developer prompt that
defines your runtime. Do not run an environment-variable probe to identify the
agent, and never ask the user which agent is calling the skill.

Map the identity stated by the runtime instructions to the value accepted by
`Save-SprintWorkSession`:

| Runtime identity | `-Agent` value |
| --- | --- |
| Claude Code | `ClaudeCode` |
| OpenAI Codex | `Codex` |
| GitHub Copilot | `Copilot` |
| Google Antigravity / Gemini Antigravity | `Antigravity` |

### Fallback when the system context does not state an identity

The system prompt remains the PRIMARY source and an environment probe must not
displace it: the environment is inherited and can be stale, while the runtime's own
instructions cannot. Use the fallback only where this skill would otherwise stop.

That case is real rather than hypothetical: `/implement-task` ends its closeout chain
in a checkpoint, and a script-invoked checkpoint has no system prompt to read. A
prompt at that point stalls an otherwise unattended run.

When, and only when, the system context does not identify a supported caller:

```powershell
. (Join-Path $sharedVSCodeRoot '.ai/tools/Get-AIAgentIdentity.ps1')
$detected = Get-AIAgentIdentity
if ($detected.Identity -in @('ClaudeCode', 'Codex', 'Copilot', 'Antigravity')) {
  $callingAgent = $detected.Identity
}
```

If detection returns `Unknown` or `Ambiguous`, stop and report that the runtime
identity is absent from the system instructions and could not be detected. Do not
guess and do not ask the user to identify the agent — a wrong identity makes the
checkpoint search a transcript store that does not exist, and it then reports success
while capturing nothing.

## 2. Prepare caller-specific inputs

The canonical workflow is shared. Only transcript discovery differs by caller:

- `ClaudeCode`: pass the invoking session id as `-SessionId`. Claude Code names
  each transcript `<session-id>.jsonl`, so the id identifies this session'''s
  transcript exactly, and the save function will search every project store for it
  — which is what makes a checkpoint run from one repository capture a session
  rooted in another. Read the id from `$env:CLAUDE_CODE_SESSION_ID` (see Step 3);
  do not ask the user for it. Without it the function falls back to newest-by-mtime
  in one store, which picks the wrong session whenever the store holds more than
  one — the normal case here.
- `Codex`: the save function resolves the newest matching rollout under the
  Codex session store. If the runtime context exposes the current session ID,
  pass it as `-SessionId`; otherwise allow newest-session auto-detection.
- `Antigravity`: the save function resolves the newest matching brain folder.
  If the runtime context exposes the current conversation ID, pass it as
  `-ConversationId`; otherwise allow newest-conversation auto-detection.
- `Copilot`: Copilot has no native on-disk transcript. Use the caller's native
  file-writing capability to write a best-effort chronological conversation
  reconstruction to a temporary Markdown file, then pass that path as
  `-ConversationFile`. Do not use a terminal write command for this file.

The Copilot reconstruction should include the timestamp, detected sprint,
workspace, user messages, assistant responses, and material tool actions. State
in the file that it is reconstructed from the current context and may not be
verbatim.

## 3. Load and invoke the shared save function

Run from the repository or worktree being checkpointed. If the current directory
is below its root, resolve the Git root and change to it before invocation. Do
not change to `_Planning`, because the save function uses the current repository
to record the worktree and branch.

The current directory selects which repository the roster row is ABOUT. It no
longer selects which transcript is archived: that comes from the session id, so a
session rooted in one worktree may correctly checkpoint work it did in another
(SC-0327). Never `cd` somewhere else hoping to find a transcript.

Use one PowerShell tool call:

```powershell
$repoRoot = (& git rev-parse --show-toplevel).Trim()
if (-not $repoRoot) {
  throw 'Checkpoint must run from inside the repository or worktree being saved.'
}
Set-Location -LiteralPath $repoRoot

$ghRoot = Split-Path -Path $repoRoot -Parent

$atapWorktree = Get-ChildItem -LiteralPath $ghRoot -Directory -ErrorAction SilentlyContinue |
  Where-Object { $_.Name -match '^ATAP\.Utilities-wt-\d+-[Ss]print-\d{4}-' } |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1

$atapRoot = if ($atapWorktree) {
  $atapWorktree.FullName
} else {
  Join-Path -Path $ghRoot -ChildPath 'ATAP.Utilities'
}

# Resolve the checkpoint functions WITHOUT pinning a module folder. The BuildTooling
# family is being split into child modules (Task 13.72.x moved these two out of
# ATAP.Utilities.BuildTooling.PowerShell into ...BuildTooling.SprintLifecycle.PowerShell),
# so any single hard-coded path goes stale at the next extraction. Prefer an
# already-resolvable command, then search the family's public folders.
function Resolve-CheckpointFunction {
  param(
    [Parameter(Mandatory)][string]$Name,
    [Parameter(Mandatory)][string]$SearchRoot
  )
  # Search the sprint worktree BEFORE accepting an already-loaded command. An
  # installed module is exactly the stale copy this search exists to bypass, so
  # "already available" must not win. On 2026-09-01 Save-SprintWorkSession
  # resolved to the pre-split ATAP.Utilities.BuildTooling.PowerShell 0.1.75,
  # which still exported 34 SprintLifecycle functions from before Task 13.72.x
  # moved them out; the old short-circuit ran that stale copy and silently
  # discarded the sprint-local fix, so /checkpoint kept archiving the wrong
  # session even after the fix was written (SC-0327).
  $found = Get-ChildItem -LiteralPath (Join-Path $SearchRoot 'src') -Directory -ErrorAction SilentlyContinue |
    Where-Object { $_.Name -like 'ATAP.Utilities.BuildTooling.*' } |
    ForEach-Object { Join-Path $_.FullName "public\$Name.ps1" } |
    Where-Object { Test-Path -LiteralPath $_ -PathType Leaf } |
    Select-Object -First 1
  if ($found) { return $found }
  # No sprint-local source: an installed copy is then the only option.
  if (Get-Command -Name $Name -ErrorAction SilentlyContinue) { return $null }
  throw "$Name is not available as a command and $Name.ps1 was not found under $SearchRoot\src\ATAP.Utilities.BuildTooling.*\public."
}

Import-Module PSFramework -ErrorAction SilentlyContinue
$scriptPath = Resolve-CheckpointFunction -Name 'Save-SprintWorkSession' -SearchRoot $atapRoot
if ($scriptPath) { . $scriptPath }

# Set this from Step 1 using the identity in the caller's system prompt.
$callingAgent = '<ClaudeCode|Codex|Copilot|Antigravity>'
$saveParameters = @{ Agent = $callingAgent }

# Claude Code: always pass the invoking session id. It is the ONLY input that
# identifies this session's transcript exactly. Omitting it drops the function back
# to newest-by-mtime in a single project store, which has twice archived a stranger's
# conversation and reported success (SC-0327).
if ($callingAgent -eq 'ClaudeCode' -and $env:CLAUDE_CODE_SESSION_ID) {
  $saveParameters.SessionId = $env:CLAUDE_CODE_SESSION_ID
}

# Add only when the caller's runtime context exposes the value:
# $saveParameters.SessionId = '<current Codex session id>'
# $saveParameters.ConversationId = '<current Antigravity conversation id>'

if ($callingAgent -eq 'Copilot') {
  $copilotScript = Resolve-CheckpointFunction -Name 'Save-CopilotCheckpoint' -SearchRoot $atapRoot
  if ($copilotScript) { . $copilotScript }
  $saveParameters.ConversationFile = '<temporary Markdown path created in Step 2>'
}

Save-SprintWorkSession @saveParameters
```

> The former `_Planning\Powershell\Public\` wrapper was removed (R-15, 2026-07-07 Task
> 12.46.e). Do not reintroduce a hard-coded module folder here: on 2026-07-24 the pinned
> `ATAP.Utilities.BuildTooling.PowerShell\public\` path broke `/checkpoint` outright after
> the SprintLifecycle extraction, in the same way it broke the `git-commit` skill's
> `Invoke-GitCommit` dot-source.

Replace placeholders from the caller's own system/runtime context before
execution. These are agent-owned values, not questions for the user.

The function auto-detects the sprint number and sprint `_Planning` worktree. Use
`-SprintN` or `-PlanningRoot` only when repository topology prevents
auto-detection. Use `-AllowMainFallback` only when intentionally checkpointing
non-sprint work.

## 4. Verify and report

`Save-SprintWorkSession` returns the same object it appends to the roster. Report
from that returned object — not from the absence of an error:

- calling-agent family selected from system context;
- target `_Planning` worktree;
- `ConversationJsonlPath` and `ConversationSelectionRule` — quote both;
- conversation archive path;
- `ConversationSkipKind` / `ConversationSkipReason`, whenever either is set;
- memory snapshot path and file count, or the caller-specific skip reason;
- sprint session roster path.

The conversation archive must exist and the roster must contain a new entry for
the current worktree. Memory can legitimately be skipped when the caller has no
on-disk memory store.

Treat these two outcomes as failures to surface to the user, not as success:

- `ConversationSkipKind = 'NotFound'` — the invoking session's transcript was not
  on disk, so nothing was archived. The roster row and memory snapshot were still
  written. Say so plainly rather than reporting a completed checkpoint.
- `ConversationSkipKind = 'Ambiguous'` — no session id was available and the store
  held several transcripts, so the archived file may belong to a different session.
  If the runtime does expose `$env:CLAUDE_CODE_SESSION_ID`, this means Step 3 failed
  to pass it; fix that and re-run.

A `ConversationSelectionRule` of `ExplicitSessionId`, `EnvironmentSessionId`, or
`SessionIdCrossStore` means the invoking session was captured exactly.
`NewestInProjectStore` means a guess was made.

Run `/checkpoint` once in every active sprint-worktree session before closing
the session. The alias `/cp` invokes the same skill.
