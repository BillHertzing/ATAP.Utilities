# Blazor and Syncfusion UI Guidelines

Rules for Blazor UI implementation and Syncfusion component work. Load this file before
changing `.razor`, `.razor.cs`, `.cshtml`, or Syncfusion-related C# files.

---

## Workflow (R-37)

For screenshot-driven or annotated UI work, use the Syncfusion workflow already defined
in the shared agents:

1. Validate that the target Blazor files, the annotated screenshot, and the change-plan
   template are present.
2. Produce a specific change plan with target files, Syncfusion component names, and
   acceptance criteria.
3. Wait for explicit user confirmation before implementation when the workflow asks for
   it.
4. Apply small, targeted edits only to files named in the approved plan.
5. Preserve dependency injection, routing, event handlers, and unrelated formatting.

---

## Blazor Static Assets

When supporting non-production environments such as `Experimental`, do not assume that
Blazor static web assets are enabled only for `Development`. If static assets fail under
a custom environment, check whether `UseStaticWebAssets()` needs to run for that
non-production environment before investigating unrelated process or browser issues.

---

## Syncfusion Component Rules

- Prefer established Syncfusion Blazor components over hand-rolled equivalents when the
  project already uses Syncfusion for that UI pattern.
- Use exact Syncfusion component names and documented properties in plans and code.
- Keep component parameters, event callbacks, and backing C# logic aligned; do not update
  markup without checking the related `.razor.cs` or service code.
- Preserve existing Material/theme conventions unless the task explicitly asks for a
  visual redesign.
- For grids, menus, dashboards, schedulers, and layout controls, consult existing local
  examples before introducing a new pattern.

---

## File Boundaries

Only edit the Blazor files required by the task. Do not change shared routing, DI
registration, app startup, or CSS resets unless the change plan names them and explains
why they are necessary.

End of instructions.
