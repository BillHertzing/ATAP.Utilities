# ATAP.Utilities.BuildTooling.PowerShell - Project File Index

This index lists every file currently in the BuildTooling PowerShell project and gives a high-level purpose for each one. Regenerate it whenever files are added, removed, or moved.

## Project Shape

- `public/` contains exported cmdlets and developer-facing workflows.
- `private/` contains internal helpers dot-sourced by the module.
- `tools/` contains loose workstation or development setup scripts that are not exported cmdlets.
- `tests/` contains Pester coverage and fixtures.
- `Resources/`, `Documentation/`, and `Obsolete/` hold support files, docs, and retained historical scripts.
- `Obsolete/private/` retains retired internal helpers (e.g. the per-sprint ProGet feed and per-sprint database/BuildMaster scaffolding) for provenance only; no current cmdlet dot-sources them.
- Sprint planning boards now flow from authoritative `TASKS.md` to generated `TASKS.html` via `Convert-TasksMdToSprintBoard`.
- `Save-SprintWorkSession` now appends a lightweight `SprintWorkSessionRoster/SprintWorkSessionRoster-<NNNN>.jsonl` file in the sprint `_Planning` worktree so SprintEnd can verify archive coverage by worktree name.

## Sprint Lifecycle Flow

The public sprint helpers are driven by two runbooks in the SharedVSCode `.claude/agents/` folder. Use this section as the index back into the per-cmdlet entries below.

**Runbooks:**

- [SprintStartAgent](../../../../SharedVSCode/.claude/agents/SprintStartAgent.md) — opens a new sprint: SharedVSCode + downstream worktrees, junctions, sprint secrets, sprint SQL instances, BuildMaster sprint variables, sprint overview workspace.
- [SprintEndAgent](../../../../SharedVSCode/.claude/agents/SprintEndAgent.md) — closes a sprint: retrospective snapshot, downstream reset to main, sprint secret/instance/variable cleanup, sprint workspace archival, generated-artifact purge.

**Canonical sprint-boundary retargeting (V4-H03):**

- [Set-SprintBoundaryContext.ps1](public/Set-SprintBoundaryContext.ps1) — single orchestrator that retargets machine links (junctions), SharedVSCode settings symlinks, downstream workspace contexts, and registry-backed AI adapters for one or more sprint worktrees. `-Boundary Start` points everything at the SharedVSCode sprint worktree; `-Boundary End` audits adapter drift before pointing it back to stable. PowerShell profiles and ConfigRootKeys are recorded as stable-by-design no-ops. See [Sprint-Boundary-Retargeting.md](../../../SolutionDocumentation/Sprint-Boundary-Retargeting.md). `New-SprintStage1`/`New-SprintStage2` perform the equivalent Start-boundary retarget during sprint creation; SprintEndAgent calls this cmdlet directly for the End boundary.

- [Invoke-SprintAIAdapterLifecycle.ps1](public/Invoke-SprintAIAdapterLifecycle.ps1) — loads the canonical SharedVSCode registry-backed lifecycle. Start calls `Render-AIAdapters -Domain settings,permissions`; End calls `Test-AIAdapterDrift -Domain settings,permissions` before teardown. Caller order is Antigravity → Codex → Claude Code → Copilot; production defaults are project-only, and live user/global replacement requires explicit approval plus checkpoint confirmation.

**Sprint start sequence (public cmdlets, in execution order):**

1. [Test-SprintPrerequisites.ps1](public/Test-SprintPrerequisites.ps1) — Step 0 preflight (ATAP configuration-global self-bootstrap for agent shells, pwsh, gh auth, Bitwarden, BuildTooling import, SQL instances, ProGet/BuildMaster reachability, and the Task 9.7 `-BuiltModule` promotion+deploy gate).
2. [Assert-BuildMasterReady.ps1](public/Assert-BuildMasterReady.ps1) — Step 0 preflight (BuildMaster apps, pipelines, required application variables, API key).
3. [New-SprintStage1.ps1](public/New-SprintStage1.ps1) — SharedVSCode + \_Planning sprint branches/worktrees, prior-sprint structure-only task templating into the content-fresh `Tasks.Sprint<NNNN>.*` set, and permanent-feed NuGet.config (Task 10.11).
4. [New-SprintStage2.ps1](public/New-SprintStage2.ps1) — downstream sprint branches/worktrees, NTFS junctions, AI/settings links, optional `-IncludeRepos`, and a durable `-SkipDatabaseReset` recovery path. After all sprint worktrees exist it generates and verifies `OverviewSprint<NNNN>.code-workspace`, then calls `Build-AIInstructionsPerRepository` once to distribute all four per-repository instruction surfaces (Task 10.34). The normal database path passes the new ATAP.Utilities worktree root and current provisioning-script folder with `-Confirm:$false`.
5. [Reset-SprintDatabases.ps1](public/Reset-SprintDatabases.ps1) — drop/recreate the single `ATAPUtilities` database inside the existing `Dev<user>`/`Exp<user>` instances (Flyway rebuild). An explicit `-ProvisioningScriptsPath` overrides stale host settings so the active worktree's `DropAndCreateDatabase.sql` is used.
6. [New-SprintBitwardenSecrets.ps1](public/New-SprintBitwardenSecrets.ps1) — resolves the per-sprint Dev/Exp connection-string secrets. Default (Task 9.22): **derives** the deterministic Integrated-Security strings at read time and writes nothing to the vault (Stage 2 needs no `bws` write); `-WriteDerivableToVault` persists them (bws + machine access token, SC-0175). Format + derivable/credentialed classification come from [Get-DbConnectionStringSecretDescriptor.ps1](public/Get-DbConnectionStringSecretDescriptor.ps1).
7. [Set-BuildMasterSprintVariables.ps1](public/Set-BuildMasterSprintVariables.ps1) — sprint-scoped BuildMaster Application Variables.
8. [New-OverviewSprintWorkspace.ps1](public/New-OverviewSprintWorkspace.ps1) — `OverviewSprint<NNNN>.code-workspace` for the active sprint.
9. [Remove-OverviewSprintWorkspace.ps1](public/Remove-OverviewSprintWorkspace.ps1) — archive `OverviewSprint<NNNN>.code-workspace` into `_Planning/SprintRetrospective/WorkspaceArchive/`.
10. [Build-CLAUDEPerRepository.ps1](public/Build-CLAUDEPerRepository.ps1) — combined `CLAUDE.md` per repo worktree.
11. [Build-AGENTSPerRepository.ps1](public/Build-AGENTSPerRepository.ps1) — combined `AGENTS.md` per repo worktree: `ai-local.md` (AI-LOCAL) + rendered `AGENTS-base.md` core (AI-CORE), deterministic sentinels, idempotent (Task 10.23). Sibling of `Build-CLAUDEPerRepository`.
12. [Build-AgentSpecificPerRepository.ps1](public/Build-AgentSpecificPerRepository.ps1) — distributes the rendered agent-specific surfaces `GEMINI.md` and `.github/copilot-instructions.md` into each sprint repo (pure idempotent copy, stable-skip guard, and no-double-core validation).
13. [Build-AIInstructionsPerRepository.ps1](public/Build-AIInstructionsPerRepository.ps1) — single SprintStart orchestration entry point; parses the Overview workspace once, computes stable-worktree skips once, runs the three existing lane builders in canonical order, and returns per-lane plus per-repository aggregate results (Task 10.34). Called by `New-SprintStage2`.

**Sprint end sequence (public cmdlets, in execution order):**

1. [Invoke-SprintEndLifecycle.ps1](public/Invoke-SprintEndLifecycle.ps1) — typed orchestrator; always run the selected close with `-WhatIf` first.
2. [Test-SprintEndCommandSurface.ps1](public/Test-SprintEndCommandSurface.ps1) and [Test-SprintPrerequisites.ps1](public/Test-SprintPrerequisites.ps1) — validate real parameter contracts and require every changed module version in ProGet stable plus an AllUsers installation.
3. [Test-SprintEndWorktreeState.ps1](public/Test-SprintEndWorktreeState.ps1) — one structured multi-worktree clean-state gate.
4. [Test-SprintCheckpointCoverage.ps1](public/Test-SprintCheckpointCoverage.ps1) — require a reachable agent-neutral checkpoint for every selected worktree using only canonical Planning roots.
5. [Set-SprintBoundaryContext.ps1](public/Set-SprintBoundaryContext.ps1), [Reset-DownstreamToSharedVSCodeMain.ps1](public/Reset-DownstreamToSharedVSCodeMain.ps1), and [Assert-MainBranchTemplateRef.ps1](public/Assert-MainBranchTemplateRef.ps1) — audit AIAdapter drift and commit stable-target references on sprint branches before merge.
6. [Invoke-SprintEndGitHubClose.ps1](public/Invoke-SprintEndGitHubClose.ps1) — add `Closes #N`, classify required/informational/CodeSee checks, merge non-interactively, and verify the sprint issue closed.
7. [Save-SprintHistoryArtifacts.ps1](public/Save-SprintHistoryArtifacts.ps1), [Restore-SprintHistoryArtifacts.ps1](public/Restore-SprintHistoryArtifacts.ps1), and [Invoke-SprintEndOverviewClose.ps1](public/Invoke-SprintEndOverviewClose.ps1) — archive current dotted history, explicitly reconstruct reviewed older history with exact Git blob bytes and source-relative paths without overwriting different content, and archive the parent-root sprint Overview workspace.
8. [New-SprintEndHandoff.ps1](public/New-SprintEndHandoff.ps1) — atomic, self-removing worktree cleanup handoff. Stable pulls call [Test-SprintEndPullOverlap.ps1](public/Test-SprintEndPullOverlap.ps1) before `pull --ff-only`.
9. [Save-SprintEndSessionTail.ps1](public/Save-SprintEndSessionTail.ps1) — checkpoint and commit only the canonical final conversation/memory/roster tail after the Planning PR merges; never pushes automatically.
10. [Invoke-SprintEndInfrastructureCleanup.ps1](public/Invoke-SprintEndInfrastructureCleanup.ps1) — drop sprint databases, retain permanent SQL Server instances, clear BuildMaster sprint variables, and reassert the stable boundary.
11. [Test-SprintEndBoundaryState.ps1](public/Test-SprintEndBoundaryState.ps1) — final stale-reference, profile, fresh-shell, and prohibited-secret-environment audit.

SprintEnd never calls `Remove-SprintBitwardenSecrets`; it removes sprint
databases while retaining permanent SQL Server instances, and never completes a
synthetic "close sprint" task.

**Permanent (ecosystem-wide) sprint infrastructure, not per-sprint:**

- ProGet feeds are permanent: `nuget-experimental`, `nuget-development`, `nuget-integration`, `nuget-qa`, `nuget-stable`, plus the parallel `powershellget-*` and `universal-*` feed families. See [Set-BuildMasterStableVariables.ps1](public/Set-BuildMasterStableVariables.ps1) for permanent provisioning. The old per-sprint ProGet feed helpers were retired in Sprint 0007 (task B08) and live under `Obsolete/private/`.
- **Secrets policy (Task 9.21):** CI/infrastructure secrets (connection strings, ProGet/BuildMaster API keys, service-account creds) live ONLY in Bitwarden Secrets Manager (bws + DPAPI machine access token via [Get-SecretATAPBitwardenSecretsManager.ps1](public/Get-SecretATAPBitwardenSecretsManager.ps1)) or are derived deterministically (Task 9.22). They must never live in a developer's personal Bitwarden Password Manager vault. [Get-SecretATAP.ps1](public/Get-SecretATAP.ps1) defaults to Secrets Manager for all accounts (SC-0175); the personal-vault provider [Get-SecretATAPBitwarden.ps1](public/Get-SecretATAPBitwarden.ps1) is opt-in only and now **refuses CI/infra secret names**. The personal-vault `bw`/BW_SESSION writer + service-account session machinery (`New-PermanentBitwardenSecrets`, `Initialize-ServiceAccountBitwardenSession`, `Refresh-BWSession`, `Update-ServiceAccountBWCredentialFile`) was retired to `Obsolete/public/`.
- **Deterministic connection-string fallback (Task 9.22):** the `bws` _write_ path is broken, but the 12 per-sprint Dev/Exp connection strings carry no credential (`Integrated Security=True`) and are reproducible from host/tier/db/user. [Get-DbConnectionStringSecretDescriptor.ps1](public/Get-DbConnectionStringSecretDescriptor.ps1) is the single source of truth for the connection-string **format** and the **derivable-vs-credentialed** classification, shared by the writer (`New-SprintBitwardenSecrets`) and the reader (`Resolve-DatabaseSqlConnection`). The reader resolves in order: (a) real vault secret if present, (b) deterministic build when derivable, (c) hard fail if a credential is required but absent (a credentialed string is never derived). Marking a name credentialed (or adding `User Id=`/`Password=`) is a one-place config change, not a rewrite.
