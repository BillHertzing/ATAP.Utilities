# PR Merge Skill

Squash-merge a GitHub Pull Request into `main` and clean up the source branch.

## Step 1: Identify the PR

Determine which PR to merge. Check in this order:

1. If the user provided a PR number, use it directly.
2. If the current branch has an open PR, use it: `gh pr view --json number,title,state,url`
3. If ambiguous, list open PRs: `gh pr list --base main --state open`

## Step 2: Pre-Merge Validation

Run all checks before touching anything:

```powershell
# View PR state and reviewers
gh pr view <number> --json title,state,reviewDecision,mergeable,baseRefName,headRefName,commits

# Check CI status
gh pr checks <number>
```

Block the merge and notify the user if any of the following are true:

- `state` is not `OPEN`
- `mergeable` is `CONFLICTING` — must be resolved first
- `reviewDecision` is `CHANGES_REQUESTED`
- Any required CI check is failing or still in progress
- The base branch is NOT `main` (confirm with user before proceeding)

## Step 2a: SharedVSCode TemplateRef Validation

Before merging any PR that targets `main`, verify that all `.code-workspace` files
in the branch point their `atap.sharedVSCode.templateRef` to `"main"`.

Load the SharedVSCode functions and run the assertion:

```powershell
Import-Module ATAP.Utilities.BuildTooling.PowerShell -Force

$workspaceFiles = @(Get-ChildItem -Path (git rev-parse --show-toplevel) -Filter '*.code-workspace' |
    Select-Object -ExpandProperty FullName)

if ($workspaceFiles.Count -gt 0) {
  try {
    Assert-MainBranchTemplateRef -WorkspaceFiles $workspaceFiles
    Write-Host 'SharedVSCode templateRef check passed — all workspace files point to main.'
  }
  catch {
    Write-Warning $_
  }
}
```

Use the installed Production module on this validation path; do not fall back
to the historical SharedVSCode source-tree loader.

**If the assertion fails:**

- Warn the user that workspace file(s) still reference a sprint worktree.
- Ask: "Should I reset the templateRef to 'main' before merging? (yes/no)"
- If yes, run:

  ```powershell
  Reset-DownstreamToSharedVSCodeMain -WorkspaceFiles $workspaceFiles
  ```

  Then commit the workspace file changes before proceeding with the merge.
- If no, **block the merge** and return an error object.

**Never hand-edit** `.git/config`, `.gitattributes`, `.gitconfig.shared`, or
`core.hooksPath`. Use the SharedVSCode PowerShell functions exclusively.

## Step 3: Capture Worktree Context and Compose the Squash Commit Message

Before doing anything destructive, capture the worktree path and head branch name so
cleanup always has a valid target — even after the remote branch is deleted:

```powershell
# Capture head branch and worktree path BEFORE the merge
$headBranch = git rev-parse --abbrev-ref HEAD
$worktreePath = git rev-parse --show-toplevel
```

The squash commit message becomes the permanent record in `main`'s history.
Craft it carefully from the PR title, body, and individual commits:

```text
<type>(<scope>): <PR title summary>

<2-4 sentence summary of all changes in the PR>

- <key change 1>
- <key change 2>
- <key change 3>

<issue refs: "Closes #42" or "Refs PROJ-1234" if applicable>
```

- Use the same `<type>(<scope>):` Conventional Commits prefix as the PR title
- The body should stand alone — someone reading `git log` should understand the full change
- Do NOT just concatenate the individual commit messages

## Step 4: Squash Merge

```powershell
gh pr merge <number> `
  --squash `
  --subject "<type>(<scope>): <summary>" `
  --body "<body>" `
  --delete-branch
```

- `--squash` collapses all branch commits into a single commit on `main`
- `--delete-branch` removes the remote branch after merge

## Step 5: Post-Merge Cleanup

Execute the following sub-steps **in this exact order**.

### Step 5a: Remove NTFS Junction Points

Before removing the worktree directory, safely delete any NTFS junction points
inside it. Never use `Remove-Item -Recurse` on a junction — it may follow the
junction and destroy the target directory's contents.

```powershell
# Enumerate all junctions inside the worktree
$junctions = Get-ChildItem -Path $worktreePath -Recurse -Force |
  Where-Object { $_.LinkType -eq 'Junction' }

if ($junctions) {
  foreach ($junction in $junctions) {
    Write-Host "Removing junction: $($junction.FullName)"
    $result = cmd /c rmdir /q "$($junction.FullName)" 2>&1
    if ($LASTEXITCODE -ne 0) {
      Write-Warning "Failed to remove junction '$($junction.FullName)': $result"
      # STOP — do not proceed automatically
      throw "Junction removal failed. Please remove '$($junction.FullName)' manually, then re-run cleanup."
    }
  }
  # Verify: re-enumerate to confirm all junctions are gone
  $remaining = Get-ChildItem -Path $worktreePath -Recurse -Force |
    Where-Object { $_.LinkType -eq 'Junction' }
  if ($remaining) {
    throw "Junction(s) still present after removal attempt: $($remaining.FullName -join ', ')"
  }
} else {
  Write-Host 'No junctions found in worktree — skipping junction removal.'
}
```

If any junction removal fails: **warn the user with the specific junction path and
error, then stop and ask for instructions**. Do not silently continue.

### Step 5b: Switch the VS Code Window to Main

Navigate VS Code out of the worktree before deleting the directory to prevent
a locked-directory failure:

```powershell
# Open the parent repository root in the current VS Code window
$repoRoot = git -C $worktreePath rev-parse --show-superproject-working-tree
if (-not $repoRoot) {
  # Worktree IS the repo root (bare-worktree setup)
  $repoRoot = Split-Path $worktreePath -Parent
}
code $repoRoot
```

Wait briefly for VS Code to switch before continuing.

### Step 5c: Sync Local Main

```powershell
git checkout main
git pull origin main
```

Verify the local `main` SHA matches the expected squash commit:

```powershell
git log --oneline -1
```

### Step 5d: Remove the Worktree

```powershell
git worktree remove "$worktreePath" --force
```

If that fails, fall back to:

```powershell
Remove-Item -Path $worktreePath -Recurse -Force
git worktree prune
```

Verify the worktree is gone:

```powershell
git worktree list
```

### Step 5e: Delete the Local Branch

Force-delete is acceptable — the work is already squash-merged into `main`:

```powershell
git branch -D $headBranch
```

Verify the branch no longer exists:

```powershell
git branch --list $headBranch
```

### Step 5f: Prune Remote References

```powershell
git remote prune origin
git fetch --prune
```

## Step 6: Confirm

Report back to the user:

- ✅ PR number and title that was merged
- ✅ The final squash commit hash and message (`git log --oneline -1`)
- ✅ Confirmation that the remote branch was deleted
- ✅ Confirmation that all NTFS junctions were removed
- ✅ Confirmation that the worktree directory was removed (`git worktree list`)
- ✅ Confirmation that the local branch was deleted
- ✅ Confirmation that remote references were pruned
