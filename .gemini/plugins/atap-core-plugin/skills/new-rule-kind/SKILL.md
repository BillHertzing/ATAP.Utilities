## Grammar File Format

The `.ebnf` file written in step 7 must follow this structure:

```ebnf
# <KindName>.grammar.ebnf
# Language: <LanguageName>
# Kind: <KindName>
# Created: <ISO-date>
# Philote: <KindPhiloteGUID>
# Description: <one-sentence description>

<rule>            ::= <Position-1-primitive> <Position-2-primitive> ...

# --- Primitive definitions ---
<primitive-name>  ::= <terminal-or-production>
```

Production rules must reflect the `Position` ordering from `RulePrimitiveComposition`.
Cardinality maps as: `1` → bare symbol, `?` → symbol `?`, `*` → symbol `*`, `+` → symbol `+`.

## Table Insert Order

Flyway migration must insert rows in this exact sequence — foreign key constraints
enforce the dependency chain:

```
1. ATAPUtilities.PrimitiveLanguageKind    ← root anchor; all other rows FK here
2. ATAPUtilities.RulePrimitive            ← FK → PrimitiveLanguageKind
3. ATAPUtilities.RulePrimitiveInput       ← FK → RulePrimitive
4. ATAPUtilities.RulePrimitiveComposition ← FK → RulePrimitive; Position must be
                                             contiguous from 1; must match .ebnf order
```

All four inserts must be wrapped in a single `BEGIN TRANSACTION` / `COMMIT` block.
If `flyway validate` fails after writing, the migration file must be deleted and
the workflow restarted from step 8 — never hand-edit an applied migration.
